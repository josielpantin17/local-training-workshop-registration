# Presentation Guide — Local Training Workshop Registration System

## Short introduction
My project is called the Local Training Workshop Registration System. It is a C++ console program for a small training organization in Belize. It helps staff register participants, find a participant, and check registration totals for different workshops.

## Demonstration steps
1. Start the program and show the menu.
2. Choose option 1 and register a fictional participant.
3. Enter a name, a 7-to-15-digit phone number, and a workshop choice.
4. Point out the registration ID generated by the program.
5. Register a second fictional participant in a different workshop.
6. Choose option 2 to display all participants.
7. Choose option 3 and search using a lowercase version of a participant's name.
8. Choose option 4 and explain the total and workshop counts.
9. Try an invalid menu choice or invalid phone number to demonstrate validation.
10. Choose option 5 to exit.

## Explain the files
- `main.cpp` creates a `RegistrationSystem` object and calls `run()`.
- `participant.h` declares the `Participant` class and its private data.
- `participant.cpp` defines the constructor, getter functions, and display function.
- `registration.h` declares the `RegistrationSystem` class and its functions.
- `registration.cpp` contains input validation, registration, display, search, summary, and menu logic.

## Explain the programming concepts
- **Class:** `Participant` represents one workshop participant.
- **Private data:** ID, name, phone, and workshop are private so they are accessed through member functions.
- **Array:** `std::array` stores up to 100 participants.
- **Functions:** Each function handles one task, such as registering or searching.
- **Loop:** The menu repeats until the user chooses Exit. Validation loops ask again after invalid input.
- **Decisions:** `if` and `else` statements select menu actions and workshop names.
- **Strings:** Names and phone numbers are stored as strings.

## Limitations
The current version stores data only while the program is running. When the program closes, registrations are lost. It does not send messages, accept payments, or store workshop dates. It also has a fixed limit of 100 participants.

## Possible questions and simple answers

**Why did you choose this topic?**  
I chose it because local organizations run training sessions and need a way to keep participant registrations organized. BELTRAIDE's Belize Training and Employment Centre lists job-preparedness and professional-development training, including computer-skills training.

**Why use a class?**  
The Participant class keeps the information for one participant together.

**Why use an array?**  
The array stores a fixed maximum of 100 participant records.

**How does the program stop invalid menu choices?**  
It checks that the entry is a whole number from 1 to 5. If it is not valid, the program asks again.

**How does searching work?**  
The program changes the search text and saved names to lowercase, then checks whether the search text appears in a saved name.

**What is one limitation?**  
The records are not saved after the program closes.

**What would you improve?**  
I would add file storage or a database so the registrations remain available after closing the program.
